# 可视化互动叙事编辑器 — 设计文档

> 关联需求：`core/需求.md`（最终确认版）
> 文档版本：v1.0
> 实现形态：纯静态网页（HTML + CSS + 原生 JavaScript），无框架、无构建、无网络依赖，双击 `editor/index.html` 即可使用。

---

## 1. 目标与范围

在电脑上用浏览器编辑带分支的剧情 → 导出为**单个 HTML 文件** → 手机浏览器直接打开游玩。
本文档把 `需求.md` 中的功能点翻译成可落地的：**数据模型、运行语义、模块划分、界面结构、导出物结构、测试方案、实施步骤**。

范围之外（见需求第六节）：多人协作、云存储、富文本、多媒体、角色/图鉴系统、账号权限，均不做。

---

## 2. 总体架构

系统由三块组成，彼此只通过「项目 JSON」和「引擎 API」耦合：

```
┌──────────────────────────────────────────────────────────────┐
│  编辑器 editor/  （电脑浏览器）                                │
│  ┌────────────┬────────────┬────────────┬──────────────────┐ │
│  │ 列表视图    │ 节点图视图  │ 变量面板    │ 校验面板          │ │
│  └────────────┴────────────┴────────────┴──────────────────┘ │
│         ↑↓ 读写同一个 Project（store.js 单一数据源）           │
│  ┌────────────────────┐  ┌──────────────────────────────┐    │
│  │ 预览面板（试玩）     │  │ 存档 / 导入导出（JSON、HTML）  │    │
│  │ 用运行时引擎驱动     │  │ exporter.js（纯函数拼字符串）  │    │
│  └────────────────────┘  └──────────────────────────────┘    │
│  持久化：LocalStorage 自动保存 + 手动下载 .json               │
└──────────────────────────────────────────────────────────────┘
                    │ 内联：引擎源码 + 项目 JSON + 阅读界面
                    ▼
┌──────────────────────────────────────────────────────────────┐
│  导出物 story.html（手机浏览器，浅色主题）                      │
│  阅读器 reader ←→ 同一个运行时引擎 core/story-engine.js        │
└──────────────────────────────────────────────────────────────┘
```

**关键设计决策**

| 编号 | 决策 | 理由 |
|------|------|------|
| D1 | 引擎是唯一真源，编辑器预览与导出阅读器共用同一份代码 | 预览所见 = 手机所见，杜绝行为不一致 |
| D2 | 条件/效果用**结构化数据（AST）**存储，不存字符串表达式 | 免去写解析器；UI 用下拉框拼装；校验简单；渲染成中文表达式仅用于显示 |
| D3 | 引擎源码通过「生成一个字符串常量文件」内联进导出物 | `file://` 下 `fetch` 被 CORS 阻断，无法在导出时读取文件；用 `tools/build_engine_source.py` 生成 `core/engine-source.js` 保证单一真源 |
| D4 | 全部用普通 `<script>`（非 ES Module）加载 | `file://` 下不允许多文件 ES Module，双击即用的硬约束 |
| D5 | 图视图 = HTML 节点卡片 + SVG 连线，不用 Canvas | 中文文本自动换行、样式继承自 CSS，实现量小 |
| D6 | 数据版本号 + 归一化函数 | 需求会变；导入旧 JSON 时能自动补默认值并给出提示 |

## 4. 数据模型

### 4.1 项目文件（`*.story.json`）

```jsonc
{
  "format": "story-editor",       // 固定标识，导入时校验
  "version": 1,                   // 数据版本
  "meta": {
    "title": "未命名故事",         // 阅读器标题栏
    "author": "",
    "startNodeId": "n_a1b2c3d4",  // 起始节点
    "createdAt": "2026-09-27T05:00:00.000Z",
    "updatedAt": "2026-09-27T05:00:00.000Z"
  },
  "variables": [ /* Variable[] */ ],
  "nodes": [ /* Node[]，数组顺序 = 列表显示顺序 */ ]
}
```

### 4.2 Variable（全局变量）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✔ | `v_` + 8 位随机；条件/效果按 id 引用（改名不影响剧情） |
| `name` | string | ✔ | 显示名，项目内唯一，也是表达式文本里显示的名字 |
| `type` | `"number"` \| `"bool"` | ✔ | 类型 |
| `initial` | number \| boolean | ✔ | 初始值（按类型归一化） |
| `desc` | string | ✖ | 备注，仅编辑器可见 |

### 4.3 Node（剧情节点）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | `n_` + 8 位随机 |
| `title` | string | 编辑器内管理用，玩家不可见 |
| `text` | string | 正文纯文本，`\n` 表示换行 |
| `x`, `y` | number | 图视图坐标（整数），新建时自动找空位 |
| `branches` | Branch[] | 选项列表，可为空 |
| `autoRules` | AutoRule[] | 自动跳转规则（条件跳转），可为空 |

**结局节点判定**：节点没有可用后继（无命中的分支 + 无命中的自动跳转）时即为结局，不额外加标记字段，避免数据与语义不一致。

### 4.4 Branch（选项）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | `b_` + 8 位随机 |
| `text` | string | 玩家可见的选项文字（空 → 编辑器警告） |
| `target` | string | 目标节点 id；`""` 表示未设置（编辑器报错） |
| `condition` | Condition \| null | 显示条件，`null` = 恒显示 |
| `effects` | Effect[] | 点击后依次执行的变量操作 |

### 4.5 AutoRule（自动跳转 / 条件跳转）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | `a_` + 8 位随机 |
| `condition` | Condition \| null | `null` = 否则（兜底），按顺序取第一条命中 |
| `target` | string | 目标节点 id |

- 需求「无条件自动跳转」= 只有一条 `condition: null` 的规则
- 需求「条件跳转」= 多条带条件规则 + 末尾可选兜底规则

### 4.6 Condition（条件 AST）

```jsonc
// 比较
{ "type": "cmp", "varId": "v_1", "op": ">=", "value": 5 }
// 逻辑组
{ "type": "group", "op": "all", "items": [ /* Condition[]，可嵌套 */ ] }
// null = 恒真
```

- `op`（比较）：`==` `!=` `>` `>=` `<` `<=`
  - `number` 变量：全部可用
  - `bool` 变量：仅 `==` `!=`，`value` 为 `true` / `false`
- `group.op`：`all`（且）/ `any`（或）；`items` 为空视为恒真
- 复合条件示例（需求 §3）：`好感度 >= 5 且 hasKey == true`
  → `{"type":"group","op":"all","items":[{"type":"cmp","varId":"v_a","op":">=","value":5},{"type":"cmp","varId":"v_b","op":"==","value":true}]}`
- 显示文案由 `StoryEngine.describeCondition()` 渲染，嵌套时加括号：
  `好感度 >= 5 且 (hasKey == true 或 金币 > 0)`

### 4.7 Effect（变量操作）

```jsonc
{ "varId": "v_1", "op": "add", "value": 1 }    // number：add 加 / sub 减 / set 赋值
{ "varId": "v_2", "op": "set", "value": true } // bool：仅 set
```

- 数字变量 `set/add/sub` 的 `value` 取数值，非数字按 0 处理（编辑器给警告）
- 布尔变量禁止 `add/sub`（编辑器 UI 只提供「设为 真 / 假」）

## 5. 运行语义（引擎核心）

### 5.1 推进算法

```
进入节点 N：
  1. 渲染 N.text
  2. visible = N.branches.filter(b => 条件通过(b.condition, vars))
  3. if visible.length > 0:                → 展示 visible 作为选项，等待玩家点击（playing）
  4. else:
       rule = N.autoRules.find(r => 条件通过(r.condition, vars))   // 顺序取第一条命中
       if rule 存在且 rule.target 有效:    → 自动进入 target（作为同一步的延续）
       else:                              → 结局（ended）

点击第 i 个可见选项：
  1. 依次执行该选项的 effects（修改 vars）
  2. 若 target 有效 → 进入 target
     否则 → 保持当前节点并提示“该选项未设置目标节点”（编辑器侧已报错，运行时容错）
```

**为什么分支优先于自动跳转**：既能表达“有选项就给玩家选”，又能表达“条件不满足时静默转场”（条件跳转），一个算法覆盖需求 §2 与 §3。

**自动跳转的循环保护**：连续自动跳转上限 `MAX_AUTO_STEPS = 100`，超限则 `status = 'error'`，`lastError = '自动跳转超过 100 步，可能存在环'`（防止 A→B→A 无选项死循环卡死浏览器）。

### 5.2 条件求值 `evaluateCondition(cond, vars, project)`

| 情况 | 结果 |
|------|------|
| `cond == null` | `true`（恒真） |
| `group`，`items` 为空 | `true` |
| `group.all` | 所有子项为真（短路） |
| `group.any` | 任一子项为真（短路） |
| `cmp`，`varId` 不存在 | `false`，并输出警告 |
| `cmp`，number 变量 | 数值比较；变量值非数字按 `NaN` 处理（比较结果为 false，`!=` 为 true） |
| `cmp`，bool 变量 | `==`/`!=` 比较布尔；其余运算符 → `false` + 警告 |
| `cmp` 的 `value` 与变量类型不符 | 归一化：bool 变量下用 `value === true \|\| value === 'true'`；number 变量下取 `Number(value)`，`NaN` → 0 + 警告 |

### 5.3 效果执行 `applyEffects(effects, vars, project)`

- `set`：直接覆盖；number 变量做 `Number()`，bool 变量做布尔归一化
- `add` / `sub`：仅 number 变量生效，结果为 `当前值 ± Number(value)`
- 忽略未知变量 id（不抛异常，保证阅读器永不崩）
- 效果按数组顺序执行（同一变量可连续多次修改）

### 5.4 会话与回溯（`Session`）

- `vars`：会话级深拷贝，独立于项目数据（试玩不会污染编辑器数据）
- `history`：栈，每项 `{ nodeId, vars: 快照, label }`；`back()` 弹出并恢复到进入当前节点之前的状态
- `back()` 在历史为空时无效（按钮置灰）
- `restart(startNodeId?)`：重置 `vars` 为初始值、清空历史、回到指定（或项目）起始节点
- 自动跳转链只在进入节点时压入一次历史，不会把中间节点拆成多步（回溯体验更自然）

### 5.5 容错总原则

运行时不抛异常：任何非法引用（目标节点不存在、变量不存在、条件类型非法）都降级处理并记录到 `session.warnings`（预览面板可选显示）；编辑器负责把这些情况在**编辑期**用校验面板暴露出来。

## 6. 引擎 API（`core/story-engine.js`）

UMD 包装，浏览器挂 `window.StoryEngine`，Node 走 `module.exports`（供单元测试）。

| API | 说明 |
|-----|------|
| `StoryEngine.VERSION` | 引擎版本字符串 |
| `StoryEngine.SCHEMA_VERSION` | 数据版本（当前 1） |
| `StoryEngine.uid(prefix)` | 生成 id |
| `StoryEngine.createProject(title?)` | 新建空项目（1 个起始节点 + 2 个示例变量） |
| `StoryEngine.normalizeProject(raw)` | 归一化/迁移；返回 `{ project, notes[] }` |
| `StoryEngine.validateProject(project)` | 返回 `Issue[]`：`{ level:'error'\|'warn', code, nodeId?, branchId?, message }` |
| `StoryEngine.evaluateCondition(cond, vars, project)` | → boolean |
| `StoryEngine.applyEffects(effects, vars, project)` | → vars（就地修改） |
| `StoryEngine.describeCondition(cond, project)` | → 中文文案（如 `好感度 >= 5 且 hasKey == true`） |
| `StoryEngine.describeEffects(effects, project)` | → 中文文案（如 `好感度 +1；hasKey = 真`） |
| `StoryEngine.evaluateNode(project, node, vars)` | → `{ kind:'choices'\|'jump'\|'ending', choices?, target?, reason? }`（纯函数，图视图也用它标注节点） |
| `StoryEngine.createSession(project, options)` | → Session（`options.startNodeId`） |
| `Session.node` / `.nodeId` / `.vars` / `.status` / `.choices` / `.history` / `.warnings` | 状态读取 |
| `Session.text` | 当前节点正文 |
| `Session.choose(index)` | 选择选项，返回 `this` |
| `Session.back()` / `.restart(startNodeId?)` / `.goto(nodeId)` | 回溯 / 重开 / 跳转（调试） |
| `Session.on(type, fn)` / `.off(type, fn)` | 事件：`change`（状态变化）、`ended`、`warning` |
| `Session.snapshot()` | `{ nodeId, status, vars, choices:[{text,target}] }`，供变量监视与测试断言 |

`choices` 的元素结构：`{ index, branchId, text, target, description }`
（`description` = 条件的可读文案，仅预览面板展示用）

## 7. 编辑器设计

### 7.1 整体布局

```
┌───────────────────────────────────────────────────────────────────────┐
│ 工具栏  [作品名] [新建][导入][导出JSON][导出HTML]  [试玩]  [视图:列表|节点图]│
├──────────────┬────────────────────────────────────────────────────────┤
│ 侧栏 280px    │  主区域                                                │
│ ─搜索框       │  · 列表视图：节点编辑表单                               │
│ ─节点列表     │  · 节点图视图：可缩放画布                               │
│  (点击选中)   │  · 变量面板：变量表                                     │
│ ─[+ 新建节点] │                                                        │
│ ───────────  │                                                        │
│ 校验：N 错误  │                                                        │
│      M 警告  │                                                        │
└──────────────┴────────────────────────────────────────────────────────┘
```

- `store.js` 是唯一数据源：`state = { project, ui:{ view, selectedNodeId, zoom, pan, search, previewOpen } }`
- 所有视图订阅 `store.on('change', fn)`；任何修改都走 `store.update(mutator, options?)`，统一触发自动保存（防抖 400ms 写 LocalStorage）
- 视图切换只隐藏/显示 DOM，不销毁（保留图视图坐标、滚动位置）
- 渲染采用「整块重绘当前视图内容」策略：短篇量级，简单可靠，不引入虚拟 DOM；但**图视图的拖拽期间不重绘**，只更新 transform/坐标，避免指针状态丢失

### 7.2 列表视图

左：节点列表项显示 `标题`、正文首行摘要、`选项数`/`↳ 自动跳转`/`◼ 结局` 标记、`★` 起始标记；支持搜索过滤、`⋯` 菜单（复制、删除、设为起始节点、在图视图中定位）。

右：节点编辑表单

| 区域 | 控件 |
|------|------|
| 基本信息 | 标题（input）、正文（textarea，随内容自适应高度）、`设为起始节点` |
| 选项列表 | 每条卡片：选项文字、目标节点下拉、显示条件（条件编辑器）、执行效果（效果编辑器）、上移/下移/复制/删除；底部 `+ 添加选项` |
| 自动跳转 | 每条规则：条件（可为「否则」）、目标节点下拉、上移/下移（顺序即优先级）、删除；底部 `+ 添加自动跳转`；标题旁说明「仅当没有任何选项可用时生效」 |
| 底部操作 | 复制节点、删除节点、`在图视图中查看` |

选项卡片顶部实时显示逻辑摘要（如 `条件：好感度 >= 5 ｜ 效果：好感度 +1`），一眼看清。

### 7.3 节点图视图（第一期）

- 画布：`div.graph-viewport`（`overflow:hidden; cursor:grab`）+ `div.graph-world`（`transform: translate(px,py) scale(z)`）
- 节点：HTML 卡片（宽 200px）显示标题 + 正文摘要（2 行省略）+ `选项 N`/`自动跳转 N`；起始节点绿色左边框，结局节点灰色虚线边框，有自动跳转的节点带 ↳ 角标
- 连线：世界层内一个 `svg.graph-links`（`position:absolute; overflow:visible`），三次贝塞尔 + `marker-end` 箭头；选项连线灰色（带条件时橙色虚线），自动跳转连线橙色，指向不存在节点的连线红色虚线并在末端标 ⚠
- 交互：
  - 拖拽节点 → 提交时写回 `node.x/y`（`pointerdown/pointermove/pointerup` + `setPointerCapture`）
  - 拖拽空白 → 平移画布；滚轮 → 以光标为中心缩放（0.35–1.8）
  - 单击节点 → 选中（侧栏列表同步高亮）；双击 → 切到列表视图并打开该节点
  - 节点角上的快捷按钮：`编辑`、`复制`、`设为起点`、`删除`
  - 工具栏：`自动布局`（从起始节点 BFS 分层，层内按列表顺序，`GAP_X=280, GAP_Y=150`）、`适应窗口`（按包围盒算缩放平移）、`重置视图`

### 7.4 变量面板

- 表格：名称、类型、初始值、备注、引用次数（条件 + 效果中出现的次数）
- 操作：新增、删除（有引用时二次确认并说明引用位置）、改名、改类型（提示重置相关条件运算符）、改初始值
- 重名/空名实时提示（红框）

### 7.5 测试预览（需求 §5）

- 起始位置：默认项目起始节点，可在下拉里选任意节点后点「从这里开始」
- 可交互：正文、选项按钮、结局提示、「重新开始」、「返回上一步」
- 调试栏：变量监视表（名称 / 类型 / 当前值，值变化时高亮 300ms）、已走步数、历史节点列表（点击可回退到该步）、警告列表（悬空目标、自动跳转成环等运行时警告）
- 预览会话与编辑器数据隔离；预览打开期间编辑器变更不会影响已开始的会话（重新开始才加载最新数据）

### 7.6 校验面板（编辑器常驻）

底部一行显示 `N 错误 / M 警告`，点击展开列表；点击条目跳转到对应节点的列表视图并高亮问题控件。校验规则：

| 级别 | 规则 |
|------|------|
| 错误 | 起始节点不存在；选项未设置目标节点；选项目标节点不存在（悬空跳转）；自动跳转规则未设置目标节点 |
| 警告 | 节点标题为空；节点正文为空；选项文字为空；变量名重复或为空；条件/效果引用了已删除的变量；节点不可达（从起始节点 BFS 到不了）；纯自动跳转链成环 |

### 8.2 阅读器交互

- 打开即从起始节点开始，正文段落 `\n` → `<br>`
- 选项按钮全宽排列；无可用选项且有自动跳转时静默转场；结局时隐藏选项、显示「— 完 —」与「重新开始」
- 底部固定「← 返回上一步」（历史为空时禁用）与进度（`第 N 步`）
- 若出现运行时警告（如悬空目标），正文下方显示一行灰色提示，不打断游玩

### 8.3 样式要点（浅色主题 / 手机适配）

- 背景 `#f6f6f3`，正文 `#2b2b2b`，强调色 `#2f6b4f`
- 正文 `font-size:17px; line-height:1.9; word-break:break-word`
- 内容最大宽度 `720px` 居中；左右内边距 `20px`；底部 `env(safe-area-inset-bottom)`
- 选项按钮：`min-height:48px`、圆角 10px、白底 + 细边框、按下时浅灰
- 无横向滚动（`overflow-x:hidden`）、无缩放抖动（`text-size-adjust:100%`）、`color-scheme: light` 保证输入/按钮不跟随系统深色

### 8.4 脚本契约（供自动测试使用）

导出物固定包含三个带 id 的 `<script>`，测试据此提取：

| id | 内容 | 提取方式 |
|----|------|----------|
| `engine-js` | 引擎源码 | 正则 `/<script id="engine-js">([\s\S]*?)<\/script>/` |
| `story-data` | 项目 JSON（已转义 `<` → `\u003c`） | 同上，再 `JSON.parse` |
| `reader-js` | 阅读器逻辑 | 同上，`new Function('window','document', src)` 可执行 |

阅读器脚本本身不写任何 IIFE 之外的状态，所有 DOM 访问集中在 `startStoryReader(document, window)` 中，并在末尾以
`if (typeof document !== 'undefined' && typeof window !== 'undefined') startStoryReader(document, window);`
自动启动 —— 这使 Node 端的极简 DOM 桩也能真实驱动阅读器（见 §11）。

## 9. 引擎源码内联机制（无构建方案）

问题：导出时要在浏览器里拿到引擎源码文本拼进 HTML，而 `file://` 下 `fetch/XHR` 读取本地文件被 CORS 拦截。

方案：

1. `core/story-engine.js` 是唯一真源；
2. `tools/build_engine_source.py` 读取它，生成：

```js
// 自动生成，请勿手改。源文件：core/story-engine.js
// 重新生成：python tools/build_engine_source.py
window.STORY_ENGINE_SOURCE = "……引擎源码（JSON 转义后的字符串）……";
```

3. `editor/index.html` 先 `<script src="../core/story-engine.js">`（提供运行时对象 `window.StoryEngine`），再 `<script src="../core/engine-source.js">`（提供导出用的源码文本）；
4. `exporter.buildStoryHtml(project, window.STORY_ENGINE_SOURCE)` 把源码原样内联到 `<script id="engine-js">`。

保证：预览用的引擎与导出物内的引擎**逐字节相同**。引擎改动后需重新运行生成脚本（README 中写明）。

## 10. 存储与导入导出

| 场景 | 实现 |
|------|------|
| 自动保存 | `localStorage['story-editor:project:v1']`，防抖 400ms；启动时若存在则自动载入，并与 `samples/demo-story.json` 无关 |
| 新建项目 | 确认后 `StoryEngine.createProject()`，清空 LocalStorage 中的当前项目 |
| 导入 | `<input type="file" accept=".json">` → `FileReader` → `normalizeProject` → 失败时报错（`format` 不匹配 / JSON 语法错误），成功时提示归一化 notes |
| 导出 JSON | `new Blob([json], {type:'application/json'})` + `URL.createObjectURL` + 隐藏 `<a download>`；文件名取 `meta.title` 清洗后的值 |
| 导出 HTML | `exporter.buildStoryHtml()` → Blob（`text/html`）→ 下载 `作品名.html`；导出前先跑 `validateProject`，有 error 时提示「仍要导出 / 取消」 |
| 兜底 | LocalStorage 写入失败（隐私模式/超限）→ 顶部提示「自动保存失败，请手动导出 JSON」 |

## 13. 边界与不做

- 不做撤销/重做栈、版本历史、云同步（如需，后续可加「快照数组」而不改数据结构）
- 不做富文本：正文支持 `\n` 换行，不支持 Markdown/HTML（防止 XSS 与导出物复杂化）
- 不做多结局收集、成就、自动存档（阅读器只保留「返回上一步」）
- 不做节点图自动排版的力导向算法，只用 BFS 分层 + 手工拖拽微调
- 不做编辑器多语言、主题切换（仅预览/导出为浅色，编辑器为深色工作台）
